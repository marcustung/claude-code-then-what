# 退件單（範例：訂單取消 PR）

| 欄 | 內容 |
|---|---|
| 退件對象 | PR #（合成）：`Cancellation.Cancel` 實作與七組測試 |
| 退件理由 | 需求只提「未出貨可取消」，程式將 `Paid` 直接接成 `RefundRequested`（`Cancellation.cs` 第 21 行）；此規則無來源。測試「Unshipped+paid: refund requested」的預期為模型假設，非規則 |
| 規則來源 | 無（需求工單未提退款；規格文件無對應段落） |
| 要求的修正 | 二擇一：(a) 取消不負責退款：移除 `RefundRequested = order.Paid`，改為 false 並更新測試；(b) 取消需觸發退款：由訂單 Owner 提供規則（哪些取消要退、部分付款如何處理），先寫規則再由規則推導驗收案例 |
| 另需回答 | 已出貨取消的失敗如何回傳（靜默／例外）；已取消重複呼叫的期望；`Paid` 布林是否足以表達 |
| 重跑條件 | 同一介面、同一組測試框架；規則確認後測試預期由規則推導 |
| 負責人 | 規則：訂單 Owner；修正：作者；判定：Reviewer |
| 判定方式 | 規則來源附上且測試預期對得回規則段落 → 接受；否則維持退回 |
