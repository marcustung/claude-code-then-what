# Day 28 Desktop 排程實驗：契約放進 Desktop 排程，哪些守得住？（2026-10-12，跑前寫定，跑後只追加）

Day 28 的 `claude -p` 實驗（`../day28-schedule-lab`）用外層腳本模擬排程器。官方文件說 Desktop 排程「上一輪還在跑會跳過」「權限模式 Manual 時遇到沒放行的工具會停住等核准」，但我沒親自驗過；`STOP` 這種派送前煞車在 Desktop 排程裡要放哪，文件也沒寫。本實驗用真的 Desktop 排程任務跑同一個通知檢查，看三件事。

## 設定

- 本機教學服務：`../day28-schedule-lab/service.py`，port 8765，模式 `new`（每次都開新單），資料目錄 `C:\<AUTHOR>\d28-desktop-work\svc`。
- 工作目錄：`C:\<AUTHOR>\d28-desktop-work`，放兩支工具 `check_notifications.py`（唯讀）、`open_item.py`（開單）。**偏離 day28-schedule-lab：** `open_item.py` 每次等 45 秒（原 20 秒），讓一輪確定超過 1 分鐘。
- 排程任務以 Claude Code Desktop 的排程任務建立（taskId `d28-desktop-lab`），提示自包含、要求最後輸出固定格式。
- 驗收看服務端 `requests.jsonl`、`items.json`，以及任務的執行紀錄（`list_task_runs`）；不採信 Claude 自述。
- 跑完刪除排程任務。

## 三組

| 組 | 做法 | 事前預期 |
|---|---|---|
| E1 權限 | 任務建好，不放行任何工具，直接 Run now | 停在等核准：執行狀態一直是 running，服務端零請求 |
| E2 重疊 | 工具放行後，排程改為每分鐘一次，觀察約 6 分鐘後暫停 | 執行場次少於觸發次數；服務端沒有兩輪交錯的請求。但每一輪都是新工作階段、服務是 `new` 模式，**不重疊不等於不重複**：預期單數會隨輪數累加（每輪 2 張） |
| E3 煞車 | 工作目錄放 `STOP`，並在工作目錄 `.claude/settings.json` 設 `UserPromptSubmit` hook：有 `STOP` 就擋下 | 不確定。若排程工作階段會載入該目錄設定並觸發 hook，服務端零請求；否則照常開單 |

## 判讀界線

- 各組只跑一次，只示範現象，不估發生率。
- E3 若 hook 沒觸發，可能是工作目錄或設定來源不同，不直接推論「Desktop 排程不支援 hook」，要記下實際工作目錄。

## 結果（2026-10-12 台北時間 00:10–01:05，即 2026-10-11 16:10–17:05 UTC；以下時間皆為 UTC）

逐輪紀錄見 `runs/20261011T1610Z/task-runs.json`；服務端紀錄 `requests.jsonl`、`items.json`；hook 呼叫紀錄 `hook.log`。

### E1 權限：符合預期，而且比預期嚴重

- 16:10:33 Run now，9 秒後呼叫第一個 PowerShell，停住；5 分鐘服務端 0 請求。
- 使用者「允許一次」後，又停在下一個工具（Read）。
- **卡住的這一輪擋住了之後所有排程**：16:18:38 起改成每分鐘觸發，到 16:25:21 共約 7 次觸發，**一輪都沒有啟動**，`lastRunAt` 停在 16:16:25。執行紀錄（`list_task_runs`）裡看不到這 7 次。
- 16:25:21 實驗者停止那一輪，**紀錄仍是 succeeded**。
- 權限對話框只有三個選項：拒絕、允許一次、允許並切換至「自動」模式（本工作階段）。**沒有 always allow**（Claude 下的是 `Set-Location ...; Get-ChildItem; python check_notifications.py` 這種組合指令）。某次核准被寫進工作資料夾的 `.claude/settings.local.json`，存的是整條指令原文（`approval-saved-settings.local.json`）。
- 之後兩輪（16:25、16:35）都又停在權限，靠人逐次放行才跑完。直到使用者把任務的權限模式改為「自動」，16:49 起才不必人介入。
- **未預期：** 建任務時沒指定模型，執行用的是 `claude-opus-5-5`（預設）。

### E2 重疊：跳過有效，重複照樣發生
