# Day 28 排程實驗：同一個查核任務定期跑，重疊、重複、空跑、連續失敗時會怎樣？（2026-10-11，跑前寫定，跑後只追加）

## 問題

把每天凌晨的通知對帳交給排程跑，沒有人在旁邊。Claude Code 官方文件對 `claude -p` 搭配作業系統排程時「上一輪未結束又觸發」沒有說明；每次觸發都是新工作階段。本實驗看四件事：

- A 重疊：上一輪還在跑，下一輪又觸發，會不會開出重複的待處理事項？
- B 重複事件：資料裡同一個異常出現兩次（像自動產生的影子單），會不會開兩張？
- C 空跑：沒給工具權限時，排程會不會「看起來成功」？
- D 連續失敗：資料源一直壞，外層能不能停止派送、交回人？

## 共用設定

- 教學用本機服務（`service.py`）同時扮演通知資料源與待處理事項系統：
  - `GET /notifications`：今天 5 筆通知 N1–N5，其中 2 筆異常（`O-1002 timeout`、`O-1004 bounced`）。D 組固定回 503。
  - `POST /items`：開待處理事項。模式 `new`：每次都開新的一張；模式 `dedupe`：以「訂單＋異常類型」為鍵，已存在就只把次數加一、回傳同一張。
- Claude 只有兩支工具（`--allowedTools` 只放行這兩支，`--tools Bash`）：
  - `python check_notifications.py`：唯讀，取今天的通知狀態。
  - `python open_item.py <訂單> <異常類型>`：開待處理事項；故意等 20 秒才回應（模擬下游慢）。
  - 沒有查詢既有事項的工具。
- sonnet、`claude -p`、`--max-budget-usd 1`、停用 hooks 與記憶、工作目錄在 repo 外（`C:\<AUTHOR>\d28-work`）。
- 觸發由外層腳本 `run.py` 模擬排程器；鎖、停止派送都是外層腳本的邏輯，不是 Claude Code 內建。
- 驗收以服務端紀錄（`items.json`、`requests.jsonl`）為準，不採信 Claude 自述。

## 各組

| 組 | 設定 | 量測 |
|---|---|---|
| A1 | 第 1 輪開始後 30 秒觸發第 2 輪；無鎖；事項模式 `new` | 每個異常的事項張數；兩輪工具軌跡 |
| A2 | 同 A1；事項模式 `dedupe` | 同上，另記每張的次數 |
| A3 | 同 A1；外層加鎖：第 2 輪觸發時發現鎖存在，不派送，寫 `skipped: previous_run_active` | 同上，另記 skipped 紀錄 |
| B1 | 單輪；資料裡 `O-1002 timeout` 出現兩筆（N2、N6，時間不同）；事項模式 `new` | 事項張數；Claude 是否指出重複 |
| B2 | 同 B1；事項模式 `dedupe` | 同上 |
| C1 | 單輪；不給 `--allowedTools`（預設權限模式） | 退出碼、`is_error`、`permission_denials`、服務端是否有任何請求、事項張數、Claude 最後說法 |
| C2 | 同 C1，加 `--permission-prompts none` | 同上 |
| D | 連續觸發 3 次；資料源固定 503。外層在每輪結束後看服務端紀錄：本輪沒有任何一次成功取得資料 → 記為失敗；連續 2 次失敗 → 寫 `STOP`；第 3 次觸發看到 `STOP` → 不派送，寫交回人紀錄 | 第 3 次是否派送；`STOP` 與紀錄內容；第 1、2 輪 Claude 是回報失敗還是「今天沒事」 |

## 事前預期（可以被推翻）

1. A1 會出現重複事項（兩輪各開一次，2 個異常共 4 張）；A2、A3 每個異常只有 1 張；A3 有 skipped 紀錄。
2. B1：提示要求「同一異常只開一張」，Claude 可能自己察覺 N2、N6 是同一件而只開 1 張，也可能開 2 張；B2 不論如何都只有 1 張，次數可能是 2。
3. C1、C2：Claude 叫不動工具，服務端沒有請求、零張事項；退出碼可能仍是 0（舊版 2.1.223 的空跑現象），Claude 可能回報「無法執行」而不是「今天沒事」。若退出碼非 0 或 `is_error=true`，照實寫「現行版本已不是靜默空跑」。
4. D：第 1、2 輪 Claude 回報資料源失敗；第 3 次不派送。

## 判讀界線

各組只跑 1 次，是現象示範，不是發生率。服務是本機教學程式；`dedupe` 證明的是「事項系統以訂單＋異常類型去重」這條約定在本機成立，不代表任何真實工單系統內建相同保證。CLI 版本 2.1.292。

| 組 | 事項張數（O-1002 timeout／O-1004 bounced） | 退出碼／is_error | Claude 最後的說法 |

| A2 無鎖、去重 | 1／1，各 count=2 | 0／false、0／false | 第 2 輪看到 `existing: true`，沒有重試，請值班人員確認是否重複 |
| A3 外層加鎖 | 1／1 | 0／false；第 2 輪未派送 | 第 2 輪由排程器記 `skipped: previous_run_active` |
| B1 重複列、每次新建 | 1／1 | 0／false | 自己指出 N2、N6 是同一訂單同一異常，合併只開一張 |
| B2 重複列、去重 | 1／1，count=1 | 0／false | 同 B1（Claude 已合併，去重沒有被用到） |
| C1 無權限、預設模式 | 0 | **0／false**，`subtype=success`，`permission_denials` 1 筆 | 「什麼都沒檢查到……這不代表沒有異常……今天的通知對帳目前還沒有完成」 |

| D 資料源 503 | 0 | 第 1、2 輪皆 **0／false**；第 3 輪未派送 | 兩輪都自行隔 5 秒重試一次，回報「沒有完成……未知，不代表沒有異常」 |

- 重疊確實發生：A1 第 2 輪在第 1 輪還在等第二張事項回應時（16:30:14）就取得資料並開單；第 1 輪 16:30:36 才結束。
- 預期 1：A1 重複、A2／A3 不重複、A3 有 skipped → **成立**。
- 預期 2：B1 可能自己合併 → **成立（合併）**；B2 count 預期可能為 2 → 不成立，因為 Claude 先合併，去重這層沒被觸發。
- 預期 3：無權限時退出碼仍為 0 → **成立**；`is_error=false`、`subtype=success`。但 Claude 的文字照實說「沒有完成、不代表沒有異常」，不是舊版「零產出卻像成功」的靜默空跑；能分辨的只有回覆文字與 `permission_denials`。`--permission-prompts none` 與預設模式在這個任務上結果相同。
- 預期 4：D 第 3 次不派送 → **成立**；外層獨立檢查（服務端沒有成功取資料）判失敗，與退出碼 0 無關。
- 合計 US$0.167（11 次派送），每次 12–58 秒。

### 判準沒涵蓋的觀察

1. A1 與中斷實驗同型：每個工作階段只知道自己做了什麼，因此「我沒有重複」在它自己的範圍內是真的，在系統層是假的。
2. 退出碼在 C、D 共 4 次失敗中全是 0。排程器若只看退出碼，4 次都會記成成功；要靠外層核對服務端、或解析 `permission_denials`／回覆內容。
3. A2 第 2 輪把 `existing: true` 解讀為「可能重複」並交回人，沒有自行重試。
