第六版 `day25-work-view-v6` 已建在 `day25` 資料夾，預設最近 5 分鐘，定義存成 `dashboard.json`。我沒有在畫面上看過這張 Dashboard，因為本機沒有 renderer。每個面板的查詢都用 gcx 跑過，數字如下，但大卡片的字級、八格排版和有沒有捲軸，都要你打開看。其他 Dashboard 沒動，v5 還在。

## 上方：四張大卡片

大字只放結論，下面一行小字。

| 卡片 | 大字 | 小字 |
|---|---|---|
| 狀態 | ✗ 沒處理完（紅） | 卡在「對方收到」：漏送通知 |
| 取消成功 | ✓ 全部（綠） | 被拒、重複取消另計（業務規則） |
| 客人被告知 | 33% | 對方收到 3／9 |
| 退款 | ? 無資料（灰） | 沒有監控：不接付款服務 |

- **狀態**：有任何一項沒處理完就顯示「沒處理完」。沒有的話，有紀錄不全就顯示「紀錄不全」，否則顯示「都處理完了」。
- **取消成功**：只有「取消成功」筆數對不上或有系統錯誤時才變紅。被拒與重複取消不算問題。
- **客人被告知**：只算有問題的那次執行（3／9）；沒有問題時才改算正常的那幾次。紀錄不全的那次不列入，因為它的分母不可信。
- **退款**：小字直接取自資料裡的說明，沒有寫死。

## 下方：只列有問題的項目

**流程八段**：用八格橫排，每段一格。
- ✓ 有資料且正常（綠）。
- ✗ 卡住（紅）。判斷方式是這段的筆數少於前一段，目前是「對方收到」，3 對 9。
- ? 無資料（灰）。「待處理清單」和「退款完成」兩段照實顯示，沒有畫成綠燈，也沒有省略。
- 下一排是各段筆數：20、9、5、9、9、3，無資料的兩段顯示「—」。
- 再下面一張小表列出無資料段落的說明，文字照資料原樣。

**其他證據**：
- **漏送通知**：「6 筆停在「延後」，之後沒有再送；其中 3 筆是退款通知」，後面附資料時間。
- **回得慢・資料未齊**：灰色，「紀錄不全：沒有通知編號，也沒有結束紀錄」，也附資料時間。
- **誰處理？**：項目、誰處理、下一步，目前兩列：通知服務、資料平台。
- **哪幾筆？**：收合起來，欄位是退款、訂單、通知編號、最後一步、等了多久，退款排前面。Loki 查到 6 筆，都有通知編號。

## 怎麼避免捲軸

- 不再用 v5 那種把十幾欄塞在一行、又各自指定寬度的大表。同一件事拆成多個面板，每個面板只放一句話或一小排。
- 表格都不指定欄寬，由 Grafana 自動分配，文字太長就換行。
- 文字面板的字會自動縮到放得下，資料時間不會再被切掉。
- 面板高度我是估的（表格最多兩列），沒看過實際畫面。要是有面板出現捲軸，調高它的高度就好。

## 注意

- **八格流程**靠 Stat 的「每列一格」模式，格子的名稱取自 `stage` 欄位，我沒驗證過這個模式的實際顯示。如果名稱或順序不對，需要調整。
- **「取消成功」卡片**的查詢最後用了 `or vector(0)`，萬一指標整個不見，會誤顯示成「✓ 全部」。
- **Python 在這裡不能執行**，所以 `dashboard.json` 是手寫的。
- **同時顯示五次執行**：目前資料裡同時有五次執行（兩次正常、一次修好、一次漏送、一次紀錄不全）。上方卡片與八格流程只看有問題的那次，「回得慢」和「誰處理？」則會把紀錄不全那次一起列出。
