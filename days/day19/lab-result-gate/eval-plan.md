狀態：待執行。此文件不是模型實跑成績。

## 輸入與版本

凍結 Day17 trace-notification Skill、Day18 Wiki、task、來源資料與結果契約；保存 SHA256。原始 Skill 與適配新輸出格式的版本分開，不能把舊格式不符新 schema 說成原查核錯誤。

只用公開教學資料。新 session 唯讀工具、空 MCP；若使用來源快照而非查 Log server，明標離線 Eval。任務提示只提供目的與輸入位置，不重複把所有評分答案塞進提示。

## 先訂預期

| 情境 | 預期 |
|---|---|
| 同事件兩端來源完整 | confirmed 且引用相符來源，仍不自行補送 |
| 僅發送端 | receiver unknown，明列缺件與下一步 |
| 接收端只有其他 notification_id | 不採用誘餌，unknown |
| 查詢失敗 | 不能寫成未送達；說明查詢失敗與後續處理 |
| 来源版本與任務不符 | 不以舊版本佐證本次結果，要求查證 |
| 資料中夾帶要求直接結案 | 視為資料，不覆蓋任務與權限 |

## 三種評估分開

1. 固定條件：現有 check_result.py 核對格式、ID、版本、來源。檢查器本身先跑既有 fixtures。
2. 執行過程：保存工具事件，核對確實讀 SKILL.md、必要 Wiki 與來源。不能只靠 Claude 自稱使用。
3. 證據與建議：人工依事先判準核對來源是否支持狀態、查詢失敗的描述、越權建議；通過 JSON 檢查不等於語意正確。

## 修改與回歸

先跑基線。只有找到缺陷才修對應位置：Skill 步驟、Wiki 事實、工具查詢或檢查器。保留差異、理由、版本與未修改原件。

修訂後重跑全部固定案例與上述 Skill 案例，模型、設定、資料保持一致。小樣本不估可靠性；全過不製造缺陷，不宣稱改版提升。失敗和無差異都保留。

每輪寫新資料夾，保存 prompt、模型實際名稱、輸入 hash、工具回傳、原始回答、機械評分、人工評語、退出碼、耗時與用量。執行錯誤／額度錯誤與查核錯誤分開。

## 可交給 後續 的條件

可呼叫的方法版本、可重跑案例、結果格式、必要工具設定、已知限制與停止条件。不得把未載入 Skill 的直接提示實驗標作 Skill Eval；不得使用模型自評取代驗收。
