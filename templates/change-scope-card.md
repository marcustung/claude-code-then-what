# 開工卡（Day 9）

需求寫好之後、進設計討論之前，把查到的差異收成一頁。每列接一個動作與一個人；「待決」擋的是設計，不是全部工作。

| 開工卡 | 內容 | 誰接 |
|---|---|---|
| 要改 | 哪個行為要變、哪些舊測試的預期要反轉 | RD |
| 要補驗收 | 現有測試沒餵過的輸入組合、規則交會的情境 | RD |
| 保持不變 | 不能順手動的行為、型別簽名、對外契約 | RD |
| 不納入 | 同資料夾裡的其他提案、範圍外的系統 | 另開票 |
| 待決 | 需求沒回答、程式看不出來的問題（附選項） | PM／業務 Owner／下游 Owner |

填法：

1. 讓 Claude Code 在唯讀模式（plan mode 或 `--tools Read,Grep,Glob`）讀需求、現況、測試、呼叫端，列差異並附檔案位置。
2. 它說「沒有」的地方，先查是真的沒有還是沒給它看；未提供的檔案不能推論成不存在。
3. 「待決」寫成有選項的問題，標明找誰；不把 Claude 的建議直接填成已接受規則。
4. 卡片版本與需求版本、程式版本一起留在工作項目裡。
